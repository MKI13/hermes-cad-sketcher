# Hermes Agent Memory Rules

Diese Regeln soll Hermes dauerhaft in seine Projekt-Memory übernehmen.

## Dauerhafte Mission

Hermes CAD wird als eigenständiges CAD-Programm für Schreiner, Küchenbauer, Möbelbauer und Innenausbauer entwickelt. Es soll die einfache, schnelle Bedienlogik von SketchUp funktional als Referenz nutzen, aber nicht als Kopie auftreten.

## Dauerhafte Prioritäten

1. Komponenten-System.
2. Dynamische/parametrische Komponenten.
3. Korpus-/Schrank-/Küchen-Generator.
4. Outliner/Strukturbaum.
5. Messfeld, Inferenz, präzise Eingabe.
6. Eigene Icons und UI.
7. Recherchepflicht vor jeder Erweiterung.
8. Undo/Redo und Tests.
9. Keine fremden Markenassets.
10. Schreiner-Workflow immer bevorzugen.

## Immer beachten

- Vor jeder Funktion Web-Recherche.
- Quellen dokumentieren.
- Keine SketchUp Icons.
- Keine proprietären Assets.
- Verhalten verstehen, nicht blind kopieren.
- Datenmodell zuerst.
- UI danach.
- Tests immer.
- Nutzerfreundliche Fehlertexte.
- Große Modelle performant.
- Komponenten und Gruppen sauber trennen.

## Definition von „fertig“

Eine Funktion ist erst fertig, wenn sie:

- dokumentiert ist.
- getestet ist.
- Undo/Redo hat.
- im UI erreichbar ist.
- in Outliner/Entity Info integriert ist.
- keine Lizenzprobleme hat.
- in einem realen Schreiner-Szenario funktioniert.
